## Was **nicht** hierher gehört

- **Arbeitsregeln** (Tonalität, Vorgehen, Freigabeprozess) → im Projekt unter **„Benutzerdefinierte Anweisungen“**, nicht als Datei.
- **Zugangsschlüssel, Passwörter, Tokens, API-Keys, Stripe-/Supabase-IDs, Kundendaten** → niemals, weder hier noch im Projektkontext.

## Pflege

- Nach größeren Releases `02`–`04` aktualisieren und das „Stand“-Datum im Kopf anpassen.
- Bei Widerspruch gilt: Code/Repo-Stand vor Doku, Ist vor Soll.
