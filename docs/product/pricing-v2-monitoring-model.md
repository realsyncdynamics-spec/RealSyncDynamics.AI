# Pricing v2 — Monitoring Model

## Product definition

The public scan is an acquisition and transformation entry point. It is **not** the recurring product unit.

The recurring product is continuous website governance and monitoring.

### Customer lifecycle

`Free first check / preview → €349 Website Transformation → Core Governance subscription → optional capabilities → optional website capacity`

## Recurring value

Core Governance is sold around the promise:

> Keep my website continuously monitored, evidence-backed and governed.

Core therefore covers a credible baseline for one website:

- recurring monitoring
- change/drift detection at the supported baseline
- evidence collection and history
- governance/compliance status
- risk findings and notifications
- reporting
- basic AI-assisted analysis

The exact monitoring cadence is an implementation/operational parameter and must not be marketed as an arbitrary scan quota.

## What is not a recurring unit

### Initial scan

The first scan establishes the baseline and creates the evidence context used by the transformation and governance workflow. It should not be represented as a monthly scan allowance.

### Website Transformation

The €349 Website Transformation is a one-time service/product action:

- initial evidence context
- Gemini transformation reasoning
- four landing-page variants
- SiteOS rendering
- before/after preview
- governance validation
- backend preservation

It is independent of subscription capacity.

## Capacity

Additional website capacity means additional websites under continuous monitoring. It is not a bundle of one-off scans.

Initial commercial bands for validation:

| Websites monitored | Commercial treatment |
|---|---|
| 1 | included in Core |
| 5 | small capacity add-on |
| 25 | growth capacity add-on |
| 100 | agency capacity add-on |
| 500+ | negotiated / Enterprise |

Capacity and capability remain independent:

- a single website may need advanced compliance;
- many websites may only need Core monitoring;
- customers must not buy unrelated capabilities to unlock more websites.

## Monitoring expansion

Where infrastructure cost genuinely increases with frequency or volume, use transparent capacity dimensions rather than calling them scans:

- monitoring frequency
- AI inference volume
- automation executions
- evidence retention/storage
- API calls
- bulk operations

Only introduce a separate charge when the marginal infrastructure cost or customer value is material enough to justify it.

## Positioning

Avoid:

> “X scans per month.”

Prefer:

> “Continuous monitoring for your website.”

And for multiple websites:

> “Monitor all your websites from one command center.”

The dashboard should show current status, changes, risks and customer communication actions across the monitored portfolio.

## Pricing guardrail

The customer should never feel that the €79 Core subscription is a trial version that must immediately be upgraded to become useful. Core is the complete entry product; additional payments buy additional scope, capabilities or scale.
